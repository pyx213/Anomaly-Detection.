工业级多变量时序异常检测实战：从传统算法到 Graph-Transformer
本项目完整记录并实现了一套端到端的多变量时间序列异常检测流水线。从基础的机器学习算法出发，逐步演进到深度学习、多变量时空建模，最终在真实的工业测试台数据集（SKAB）上，实现了基于 GAT（图注意力网络）与 Transformer 融合的 Graph-Transformer 架构。

🗺️ 技术架构演进路线 (Technology Evolution)
模型架构并非一蹴而就，而是经历了完整的工业级探索与迭代：

传统静态检测：One-Class SVM / Isolation Forest（理解异常分数断层与阈值权衡）。

单变量时序：Linear Autoencoder / LSTM（利用滑动窗口和重建误差，捕捉AWS服务器卡死异常）。

多变量时序：Multi-Var Transformer（利用自注意力机制，捕捉多传感器间的“关系断裂”）。

时空双擎初探：GCN + Transformer（引入图卷积，提取物理空间拓扑）。

终极形态：GAT + Transformer（引入图注意力机制，动态分配不同传感器的权重，极大提升了对关键节点异常的敏感度）。

🧹 核心数据工程与清洗流水线 (Data Pipeline & Cleaning)
真实世界的数据充满“毒药”（断网、极值、错位），本项目构建了高鲁棒性的清洗管道：

1.盖帽法 (Clipping) —— 对抗极端野值

问题：传感器抽风产生的 99999 极值，会严重带偏数据分布并撑爆神经网络。

做法：计算数据的 99% 分位数，使用 clip(upper=cap_value) 强制将超过该值的点“削平”。

2.前向/后向填充 (ffill/bfill) —— 对抗断网缺失

问题：传感器掉线导致连续的空值（NaN），直接入网会引发报错。

做法：用缺失点前一个有效值或后一个有效值进行填补，保证时间序列的连贯性。

3.时间重采样 (Resample) —— 对抗时间断裂

问题：网络丢包导致时间戳断层（如直接跳过 10 分钟）。

做法：使用 df.resample('1min').mean() 强行以固定频率对齐时间轴，缺失区间使用线性插值填补。

4.移动平均平滑 (Rolling Mean) —— 对抗高频毛刺

做法：取前后 5 个点的均值作为当前点，熨平传感器的高频微小抖动，防止自编码器将正常物理噪音误判为异常。

5.数据标准化 (StandardScaler) —— 神经网络的护身符

做法：将所有特征压缩至均值为 0、方差为 1 的区间。彻底解决了未标准化导致的梯度爆炸（Loss 飙至 800+）问题。

6.滑动窗口与严谨对齐

通过长度 30 的窗口切分时序构造特征；使用 true_labels[window_size-1 : ...] 严格切片，解决经典“差一错误”，确保物理时间 1 秒不差。

🩸 核心踩坑与排雷记录 (Troubleshooting & Engineering)
在开发过程中，遭遇并解决了深度学习时序建模中最棘手的几个工程问题：

遇到的问题                       根本原因分析                                最终解决方案
1. 梯度爆炸 (Loss飙升至800+)    原始物理数值直接入网，反向传播时指数级放大。    引入 StandardScaler，将特征压缩至均值为0、方差为1。
2. 模型欠拟合 (Loss停滞0.3)    早期将 GCN 与 LSTM 串联，LSTM 无法处理空间混合特征。    架构升级：弃用 LSTM，引入 Transformer 自注意力，Loss 降至 0.04。
3. 数组越界 (Inconsistent samples)    滑动窗口导致预测序列比真实标签短了 window_size-1。    严谨对齐：严禁粗暴补零，使用时间索引严格切片对齐。
4. 单点噪音过敏 (高误报)    真实传感器高频抖动，误差稍微越过阈值就报警。    双规判定后处理：连续3个点超阈值才报（防抖）；超1.5倍阈值秒报（防漏）。
5. 过拟合 (F1下降)    训练轮数过大，模型死记硬背噪音。    引入早停思维，回退到最佳轮数，并引入 Dropout 层。
6. 内存溢出 (IDE卡死)    多步预测张量变形导致内存泄漏，底层库版本不兼容。    限制单线程 os.environ["OMP_NUM_THREADS"] = "1"，简化张量操作。
💡 算法选型与工程博弈 (Algorithm Trade-offs)
重建 (Autoencoder) vs 预测 (Forecasting)：
对于变化很大的数据，预测模型比较吃力
在真实强噪音数据（SKAB）上，预测模型极易将噪音当成趋势，导致漏报严重（F1 仅 0.18）。

重建模型通过“临摹”整体流形，具备天然抗噪性（F1 达 0.31）。

GCN vs GAT：

GCN 是“端水大师”，对所有物理邻居一视同仁，容易稀释异常信号。

GAT 能自动学习邻居权重（如主泵对阀门影响力>储罐），在真实工业数据上，凭借 GAT 的动态注意力分配，成功将 F1 从 0.31 提升至 0.42。
